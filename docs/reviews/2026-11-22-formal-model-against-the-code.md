# Review: the preprint's formal model read against the code

Found by an AI agent (Claude) at the owner's request, while the mathematical statements of the preprint's appendix A were written in Lean 4 and read against the implementation (21 and 22 November 2026), at `1951633`.
Nothing here used the real screen, UI Automation, input or a model: the tests use generated boxes, generated crops, registry states built in the test and the simulated desktop.

## Findings

In all four findings the code was right and the prose was not. No production code changes. The preprint was corrected in v0.7.1; the three tests below tie the corrected statements, and the theorems behind them, to the implementation.

## A test that is not a finding

`src/application/src/engine/tests.rs`: `two_agents_on_one_engine_never_deliver_twice_on_one_snapshot`. Two agents share one engine on the simulated desktop and act in a generated order, each on the last page it received (600 steps, fixed seed). No snapshot authorises two deliveries, every refusal is `STALE_SNAPSHOT`, and the input events are exactly the deliveries. The engine has no notion of an agent; the test pins the property of its single snapshot counter from which [ADR-0039](../adr/0039-several-agents-through-one-engine-with-an-input-lease.md) starts.

## Observations left open

None of these is changed here. Each needs the owner's decision, and the first would change the dossier.

* **O3. `CachePolicy::new` accepts `min_margin = 0`.** The condition for an ambiguous match is `next - d < policy.min_margin` (`appearance.rs`). With a margin of zero an exact tie between two labels is not ambiguous and the first label wins by order. The text says a tie is unknown, which holds for any positive margin. Either the constructor refuses zero, or chapter 04 says that zero disables the margin. The thresholds of the icon cache never get defaults, so this is the operator's value either way. The behaviour is pinned as it is today by `a_zero_margin_resolves_an_exact_tie_by_label_order` (`appearance.rs`), so either decision will show as a change to that test.
* **O4. A snapshot identifier that does not parse is answered with `STALE_SNAPSHOT`.** It is a refusal, so nothing unsafe follows; the prose on the order of checks does not mention the case.
* **O5. With the adaptive rule at 2, a regional plan has exactly one region.** The limit of four regions then decides only the recorded reason. [ADR-0041](../adr/0041-two-performance-candidates-decided-by-measurement.md) proposes what to measure.
* **O6. The closure never needed more sweeps than supports plus relations plus one** in the 2,000 generated cases, which is the bound the test asserts and the argument in its comment gives. The bound is not a theorem of the model. If it is one, the limit of 1,000 sweeps can only be reached with about a thousand boxes.

## Decisions that differ from the first reading

* **The index contract was first written too weakly, and that was this review's own error.** The first patch proposed for the preprint said that an index returning at least the candidates, and only controls, was enough for the same fusion result. That was proved only for the set of candidates. It is false when the index repeats a control, because the tie rule counts claims. The applied text keeps "exactly `cand(X)`, each control once", and the model now proves that the condition is needed.
* **No test was added for H2.** The existing index tests already pin "once each" on the implementation; a generated test would repeat them.
* **The tests compare with exact arithmetic on purpose.** The generated boxes have integer corners, so every comparison of the closure is exact in `f64` and a difference between the two procedures cannot hide in rounding.
