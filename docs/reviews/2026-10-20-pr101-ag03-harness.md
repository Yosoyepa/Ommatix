# Review of PR 101: the AG-03 pixel-agent harness (offline steps)

Reviewer: Codex (`gpt-6.1-sol`, xhigh), 2026-10-20, at `df8f9df`: **CHANGES REQUIRED**, 3 P1 and 7 P2. This file
records, for each finding, the resolution and the regression test that covers it (AGENTS.md rule 10), and the
red-first evidence (rule 11). Everything is fake-only: no real input, window, screen, DLL or provider was used.

## Process

* **First round (df8f9df).** The code was written before its tests, so "fail first" was not met; a post-hoc
  mutation pass (18 single-guard breaks, 16 caught, the 2 survivors repaired) was used instead. The review rightly
  says that cannot establish a fail-first history. That deviation stays on record.
* **This round.** For every finding the regression test was written first and run against `df8f9df`; the red
  output was saved before any fix (`red/<class>.txt` beside this round's report, outside the repository). R7 was the
  exception in order only: its tests (`test_campaign.py`) were written after the entry-point code, then run in a
  checkout of `df8f9df` overlaid with the new tests and test support, where they fail (`main()` has no `deps`,
  `driver` or `display`, and there is no repetition, gate or pool); a mutation pass of 18 breaks of this round's
  fixes (a latch, a classifier, a stop reader, a SendInput decoder, the DPI decision, the hit-test order, the
  retry precedence, the fault classifier, the effective caps, the pool, the gate and the slot adapter) catches all
  of them.
* The four implementation readings of the first round were decided by the architect: (1) safety events are
  terminal and classified by guard and stage; (2) the reservation precedes the window evidence, confirmed;
  (3) the fingerprint excludes the proof date and the start time, confirmed, and is built from effective
  settings; (4) client area up to 1568 px with a refusal on geometry change, confirmed, conditional on a verified
  DPI context and on the real step 2.
