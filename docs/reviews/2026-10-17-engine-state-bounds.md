# Engine state bounds — 2026-10-17

Scope: offline RNF-06 evidence complementary to PERF-03, at `8587f4e` plus this PR. No requirement status or DoD box changes. Counts describe retained application/domain state between calls, not transient candidates, allocator overhead, SDK caches, RSS, GPU memory or a live soak. `Engine::retained_state_sizes()` is a local, on-demand diagnostic; neither observations nor MCP call it.

Let `G = ceil(width / tile_size) * ceil(height / tile_size)`, `C`, `W`, `A` be retained controls, words and accessible records, `E` the current fused elements, `P` configured prototypes, `I` shapes in the last detector call, `V` the current OS window list, `D` distinct effect-bearing request IDs retained since the last journal purge, and `J = JOURNAL_CAPACITY = 1024`. Bounds using evidence counts are conditional on that evidence: ports do not impose an engine-wide numeric maximum on detections, OCR words, names, discriminants or their bytes.

## PR #81 review corrections (1.0.88)

- **P2 finding → resolution → validation:** PR #80 already owns dossier version 1.0.87. This PR's entry, references and PR description use **1.0.88**; it stays first in the newest-first CHANGELOG and precedes 1.0.87 when the branches integrate. No entry from the other branch is duplicated here. The package validator accepts the reserved version gap while PR #80 is open.
- **P3 finding → resolution → regression:** unchecked `next_id += 1` panicked in debug and wrapped to zero in release at identifier exhaustion, breaking the issued-prefix invariant and permitting eventual reuse. `checked_add` now returns `IdentityError::IdentifierExhausted` before publishing an invalid candidate. `u64::MAX` is the exhausted next-ID sentinel, so `u64::MAX - 1` is the final issuable ID. Both `rnf_06_identifier_exhaustion_rejects_creation_without_wrapping_or_reusing_ids` and `rnf_06_identifier_exhaustion_discards_partially_allocated_candidates` failed first in debug and release with the old allocator. They preserve a previously retired ID, verify unchanged source state after failure, exercise successful issuance of the last ID, permit observations requiring no new IDs, and reject a later creation without reuse.

Retirement classification is equivalent to the former set **for every history that does not exhaust the 64-bit counter; exhaustion now fails closed**. The generated differential intentionally retains the old unchecked allocator as a frozen test-only reference and covers non-exhausting histories. The seeded boundary regressions cover the new rejection rather than asserting equivalence to the old wrapping behaviour. The engine's existing `fuse_and_track` maps identity errors to a failed observation before staging/commit (`observe(...).ok()?`): nothing is published and planned dirty tiles remain pending; there is no new wire error or retry policy.

## Fail-first record and limitations

The old retired set fails `registry_entries <= 1` on the first retirement. The old wide/tall pending union fails with 5 versus 3 tiles. A seeded derived-classification defect that marks active IDs retired fails the differential test at history 0 / step 0 / ID 1; the mutation was removed. Explicit ignored-test runs reproduce both unresolved growth paths and fail only their desired constant-bound assertion after checking observed growth. The ordinary suite keeps them ignored with the review path; passing tests do not claim those bounds exist.

The pending differential covers 1,000 histories of 40 transitions with successes, failures, wide/tall/square sizes, returns to a previous size and epoch bumps. Epochs increase on geometry changes, as the capturers require; a faulty provider that rolls back epochs is outside that equivalence evidence. Fixed-geometry failed-observation expectations follow the union/clear semantics of UT-14/OR-19 and UT-15/OR-20; Python remains an independent oracle, not a dependency.

Release collection measurements and before/after PERF-01 stage percentiles are published in [S0 §17](../thesis/S0_RESULTADOS.md). The diagnostics allocate only when explicitly called and add no field to MCP. Synthetic evidence does not measure UIA truncation in production, process working set, SDK caches, GPU memory, a 2-hour soak or absence of leaks. Decision 9's operator threshold, decision 6's current-code live soak, and the proposed retention policies remain owner decisions.

Normal-path per-stage latency after the exhaustion guard was measured separately on clean commit `f0589bee584e2c890ca68c48bd88591d22da5a49`, with the same PERF-01 arguments. S0 §17.3 and `state-bounds-core-exhaustion-2026-10-17.json` preserve that run alongside the pre-guard evidence; the boundary itself is tested by seeded regressions, not by exhausting IDs in the latency run.
