## F1 (P1). The ledger transaction was not atomic across proxy processes

Finding: two proxies with separate `threading.Lock`s both read 0 and both wrote 1 against a budget
of 1; the `.tmp` name was fixed; the per-goal cap lived in a process-local counter.
Resolution: `reserve()` takes an inter-process lock (`<ledger>.lock`, `msvcrt.locking` or
`fcntl.flock`) around the whole read, check and write; the ledger is JSON `{v, total, goals}` and
the goal's count lives in it under `--goal-id` (`--max-live-goal`), so restarting the proxy cannot
reset it; the write goes through `tempfile.mkstemp` in the same directory, `fsync`, then
`os.replace`, and the temporary file is removed on failure. A held lock, an old-format or malformed
ledger and a failed write all refuse the live call.
Regression: `test_concurrent_processes_never_oversell_the_budget` (8 processes, budget 3, exactly 3
reserved), `test_restarting_the_proxy_for_the_same_goal_does_not_reset_its_cap`,
`test_a_held_lock_refuses_instead_of_racing`, `test_a_crash_while_writing_leaves_the_old_ledger_and_no_temporary_file`,
`test_the_reservation_is_committed_before_anything_is_forwarded` (crash point after the
reservation), `test_a_refusal_before_the_reservation_changes_nothing` (crash point before it),
`test_the_temporary_name_is_unique_per_writer`, `test_a_corrupt_or_old_format_ledger_refuses_every_live_call`.

## F2 (P1). Relative paths meant different files to the runner, the proxy and the engine

Finding: `--ledger LIBRO.txt` was read by the runner in the launch directory but written by the
proxy in the per-run scratch directory; a relative `--config` stopped resolving under scratch; the
runner created the stop file relative to its own directory while the engine resolves it against the
configuration file's directory; `summarise.py --out resumen.json` wrote into the checkout.
Resolution: `parse_args` makes every path argument absolute once, against the launch directory
(`absolute_arg`), and children get absolute paths only. The proxy refuses a relative, drive-relative,
extended-length, device or alternate-stream `--log`/`--ledger`, and anything that resolves (symbolic
links and junctions followed, `os.path.realpath`) into a checkout. The runner resolves the
configuration's `stop_file` and `purge_file` with the engine's rule (`engine_path`, from
`Config::resolve_path`: relative against the file's directory), validates the resolved paths and
creates the stop file at exactly that path. `summarise.py --out` is made absolute and checked.
Regression: `PathTests` in `test_run_goal.py` (relative arguments resolved once; every child gets
absolute paths; a ledger in a checkout refused; stop and purge resolved like the engine), `PathTests`
in `test_proxy.py` (relative and ambiguous forms, symlink into a checkout, ledger and goal id
required), `test_a_stop_file_that_resolves_inside_a_checkout_is_refused`,
`test_a_safety_event_engages_the_engines_stop_path_before_another_goal_begins` (stop path next to a
configuration in another directory), `test_the_summary_is_never_written_inside_the_repository`.

# Review of PR 88 (head `107cf66`): F1-F4

The reviewer confirmed the ordinary editor-folder shape and the headline token example, and found four

## F1 (P1). Cleanup deleted an existing run's note after exclusive creation refused ownership

Resolution: `EditorRun` records ownership (`owned`), set only once `RunTree.create` has succeeded.
`cleanup` removes nothing when the run does not own the folder (`{"left": [], "not_ours": true}`), adopts
the editor's note only if the folder still resolves to what was created and has no reparse point in its
path (otherwise it leaves everything and reports it), and otherwise lets the tree remove exactly what it
recorded. Known refusals are `EditorRunRefused` with a closed reason (`run_folder_already_exists`,
`run_folder_not_created`, `temporary_directory_or_run_id_refused`, and the F2/F3 reasons); `run_goal`
records them as an aborted attempt (`the editor's run folder was refused: <reason>`), starts no
application and runs the finally path harmlessly. Not relying on id uniqueness.
Tests: through `run_goal` a colliding directory with a note and an unrelated file survives byte for
byte, the attempt is recorded as aborted and no application starts; cleanup before and after a refused
creation removes nothing; an owned folder is still cleaned (note removed, an entry it did not create
left and reported); a folder swapped for a link after creation is neither adopted nor removed (the
target's note survives); other closed refusals abort the attempt instead of raising.

## F2 (P2). A parent junction caused creation outside the temporary root

Resolution: before anything is created `EditorRun` checks that the temporary directory exists and has no
reparse point in its path, and that `<temp>/ommatix-e2e`, if it exists, is a real directory and not a
reparse point; it refuses otherwise (`temporary_directory_redirected`, `shared_parent_redirected`,
`shared_parent_not_a_directory`). After creation it re-checks the run folder's chain. The guard
`editor_folder_problem` refuses a reparse point anywhere in the folder's or the temporary directory's
chain (symbolic links and junctions, file attribute 0x400), as a second line. The post-creation check
of the previous head was too late to protect the outside directory; this one is before.
Tests: with a junction (Windows) or symbolic link as the shared parent, `create` raises before making
anything, the outside directory still holds only its sentinel, bytes unchanged, and through `run_goal`
no application starts; a redirected temporary directory is refused; the guard refuses an aliased chain
whose resolved shape is fine; and with the real S4 helpers on Windows the outside target stays
unchanged.

## F3 (P2). Python accepted a folder Rust rejects because it erased filesystem casing

Resolution: `editor_folder_problem` no longer normalises case. It resolves both paths strictly (the
canonical stored names, as Rust's `canonicalize`), requires the temporary directory to be a component
prefix (the drive prefix compared case-insensitively, every name exactly, as `Path::strip_prefix`
does), and the two components below it to be exactly `ommatix-e2e` (case-sensitive, as
`*root_dir != OsStr::new(RUN_ROOT)`) and a valid run id (any case). Anything that could make the two
disagree is refused: an unresolvable path, a reparse point in the chain. `EditorRun` also refuses, before
creating anything, a shared parent that exists stored under another case (`OMMATIX-E2E`), and never
renames or adopts it.
Tests: the previously accepted uppercase parent is refused by the guard and before creation, with
nothing created or renamed; the ordinary parent is accepted and the run id may be any case; and a parity
test compiles the editor's own `valid_run_id` and `SaveFolder::new` (extracted from its source with
brace matching, standard library only, no GUI code) as a probe and compares its verdict with the
guard's on nine cases (ordinary, run id in another case, uppercase and mixed-case parents, a space in
the id, 64 and 65 characters, the old scratch root, a `runs` folder). A constant test also asserts the
case-sensitive comparison is still what the editor's source does.

## F4 (P2). Historical reports presented uncached input as per-message context

Resolution: a per-message entry counts toward the context figure only if both cache fields are present
(a measured zero counts; absent or null is unknown). Entries without them are reported separately:
`context_per_message_coverage` (`measured` / `unavailable`), and the fresh-input median of the unknown
ones is `fresh_input_per_message_median_extra_uncached_only`, labelled in the text. With no measured
message the rendering says `unavailable (historical report: the per-message cache fields were not
kept; [extra, uncached input only] median ...)`; with a mix it reports the median over the measured
messages and how many historical ones were left out. The session totals from `cli_usage` and the
labelled stream fallback are unchanged; nothing is spread from a session total.
Tests: legacy report (median not 2.0; coverage 0/2; totals 31,001 / 1,490 / USD 0.00299715 intact),
rendering, mixed old and new, measured zero versus null, current reports and the fallback unchanged.
